
## Запуск и отладка

Расширение работает внутри самого VS Code, поэтому вы используете два окна VS Code:

- в первом окне вы пишете и отлаживаете код
- второе окно, Extension Development Host, — обычный VS Code с загруженным расширением

Шаги:

1. Откройте эту папку в VS Code.
2. Нажмите `F5`. Конфигурация запуска `Run Extension` запускает компилятор TypeScript в режиме наблюдения и открывает второе окно.
3. Во втором окне откройте файл `.py` и попробуйте функцию, над которой работаете.
4. Правьте код в первом окне. Задача наблюдения перекомпилирует код при сохранении. Во втором окне выполните `Developer: Reload Window` (`Ctrl+R`, на macOS `Cmd+R`), чтобы загрузить новую сборку.
5. Точки останова ставьте в первом окне. Вывод `console.log` появляется в его консоли отладки.

## Команды

| Команда            | Что делает                                                        |
| ------------------ | ----------------------------------------------------------------- |
| `pnpm run compile` | Один раз компилирует TypeScript в `out/`                          |
| `pnpm run watch`   | Перекомпилирует при каждом сохранении                             |
| `pnpm run lint`    | Проверяет `src/` с помощью ESLint                                 |
| `pnpm test`        | Компилирует, проверяет, затем запускает тесты в настоящем VS Code |

При первом запуске `pnpm test` копия VS Code скачивается в `.vscode-test/`, поэтому один раз нужен доступ к сети. В `.npmrc` включён `enable-pre-post-scripts`; без него pnpm пропускает компиляцию и проверку перед тестами.

## Тесты

- Тесты лежат в `src/test/` и называются `*.test.ts`. Используется Mocha.
- Каждое исправление ошибки сопровождается регрессионным тестом, который без исправления не проходит.
- Проверяйте поведение, а не только «нет исключения»: для автодополнения проверьте, какие элементы возвращаются для заданной строки кода.
- Тесты не должны использовать настоящую сеть. Замените клиент Iconify заглушкой.

## Локализация

Расширение следует языку интерфейса VS Code. Собственной настройки языка у него нет, запасной язык — английский.

- Текст в `package.json` (названия команд, описания настроек) использует ключ вида `%pyside-iconify.search.title%`. Английский текст лежит в `package.nls.json`; каждый перевод — в `package.nls.<locale>.json`.
- Текст в коде проходит через `vscode.l10n.t("...")`. Переводы лежат в `l10n/bundle.l10n.<locale>.json`, а `package.json` указывает на эту папку полем `l10n`.
- Никогда не склеивайте куски фраз. Используйте подстановки: `vscode.l10n.t("Unknown parameter {0}", name)`.
- Локали: `en` (оригинал), `zh-cn`, `ja`, `ko`, `es`, `fr`, `de`, `ru`, `pt-br`.
- Не зашивайте английский текст для пользователя больше нигде.

## Соглашения

- TypeScript в строгом режиме. Без `any` в экспортируемых сигнатурах.
- Проверки не гадают. Сообщайте о проблеме, только когда она очевидна; то, чего нельзя знать (например, значение из переменной), не трогайте.
- Никогда не блокируйте ввод. Запросы к API Iconify откладываются (debounce) и кэшируются, а любая функция, которой не нужна сеть, работает без неё.
- Комментарии минимальны: для чего функция и что значат её параметры. Без истории отладки.
- Без эмодзи в коде, документации и сообщениях коммитов.
- Сообщения коммитов следуют Conventional Commits: по-английски, строчными буквами, в одну строку, например `feat: add icon search command` или `fix(completion): ignore strings outside calls`. Типы: `feat`, `fix`, `docs`, `ci`, `chore`.

## Переводы

README и эта страница выходят на нескольких языках в `docs/`. Английский (`README.md`, `CONTRIBUTING.md`) — первоисточник. Перевод сохраняет те же заголовки, таблицы и блоки кода, что и английская версия. Исправления переводов приветствуются и входят в число самых простых первых вкладов.
